# Supply Chain Security

Controls for Python dependency integrity, vulnerability scanning, and release artifact traceability (P0 handoff §12.1 item 22, §26.6).

## Dependency locking

| File | Purpose |
| --- | --- |
| `requirements.txt` | Human-edited direct dependencies with compatible version ranges. |
| `requirements.lock` | Fully pinned transitive closure generated by `pip-compile`. Used in Docker builds and CI. |

### Regenerate the lock file

After changing `requirements.txt`:

```bash
pip install pip-tools
pip-compile --output-file=requirements.lock requirements.txt
# Optional: add hash pinning for stricter installs
# pip-compile --generate-hashes --output-file=requirements.lock requirements.txt
```

Commit both files. CI fails when `requirements.lock` drifts from `requirements.txt`.

### Production image installs

`deploy/Dockerfile` installs from `requirements.lock` (not floating ranges) so every release image resolves the same package versions.

## Vulnerability scanning

Workflow: [`.github/workflows/supply-chain.yml`](../../.github/workflows/supply-chain.yml)

On every PR/push that touches dependency files and weekly on `main`:

1. **`pip-audit`** — scans locked packages against the PyPI advisory database; fails the job on known CVEs.
2. **Lock drift check** — `pip-compile --dry-run` must produce no diff.
3. **SBOM** — CycloneDX JSON (`cyclonedx-py requirements`) uploaded as a GitHub Actions artifact (`python-sbom`, 90-day retention).
4. **`pip freeze` snapshot** — uploaded as `pip-freeze` for point-in-time comparison.

### Local audit

```bash
pip install -r requirements.lock
pip install pip-audit
pip-audit -r requirements.lock
```

## Container image

| Control | Status |
| --- | --- |
| Immutable semver tag (no `latest`) | Enforced in Helm (`image.tag` fail) and release workflow (`v*` tags only). |
| Pinned Python dependencies in image | `requirements.lock` in Dockerfile. |
| Image signing / provenance | **Not yet** — track in release hardening backlog; use GHCR digest pinning at deploy time where possible. |

## Out of scope (v1)

- Automated image signing (cosign/Sigstore).
- Private PyPI mirror configuration (environment-specific).
- Hash-pinned `requirements.lock` in CI (optional; enable with `--generate-hashes` when corporate network allows).
