## Summary

This release ships the intervention case workflow for at-risk student follow-up, TOTP multi-factor authentication, a tenant policy layer for family-portal and attendance rules, and a set of P0 audit fixes (authorization, deploy pinning, session security, and health probes). Chart and export APIs now return **404** instead of **403** when a caller lacks access, matching the cross-repo QA contract. Helm and tenant-config validation enforce explicit semver image tags (no `latest` or pre-releases in staging/production).

## Changes

### User-visible features

- **Intervention workflow** — `intervention_cases` and `intervention_contacts` tables with admin UI at `/admin/interventions` and REST API at `/api/interventions` when `features.interventions` is enabled. Staff charts: `staff.intervention_uncovered`, `staff.interventions_open`, `staff.intervention_outcomes`.
- **TOTP MFA** — RFC 6238 enrolment and verification for roles configured via tenant `auth.mfaEnabled` and `auth.mfaRequiredRoles`. Browser login shows a second step; JSON API exposes `mfaPending`, `mfaEnrolmentNeeded`, and token endpoints (`/api/auth/mfa/verify`, `/api/auth/mfa/enroll/*`).
- **Policy layer** — `app/tenant/policy.py` enforces `portal.familyComparisonMode` (hide cohort benchmarks from parent/student portals in `self` mode) and attendance counting rules (`attendance.countLateAsPresent`, `attendance.countExcusedAsPresent`).
- **Health probes** — `/healthz` (liveness, no DB check) and `/readyz` (readiness, DB connectivity). Both bypass tenant hostname resolution.

### Bug fixes and security (P0 audit)

- Teacher remark POST now returns **404** when the subject is outside the teacher's section assignment (no information leak).
- Chart API returns **404** (not **403**) for forbidden or unknown chart keys; mirrors `school-analytics-config` QA regression contract (`tests/test_qa_contract.py`).
- `SECRET_KEY` is required when `DEBUG=false`; session cookies default to `Secure` outside debug mode.
- Postgres deployments skip startup DDL (`startup_ddl_enabled()`); use Alembic migrations instead.
- Tenant operator `reconcile_tenant()` binds only to the supplied `database_url` (no cross-database writes).
- Attendance import and backfill script (`scripts/backfill_attendance_term_id.py`) resolve `term_id` from `on_date`.

### Internal / ops improvements

- Helm chart requires explicit `image.tag` at deploy time; rejects `latest`. Readiness/liveness probes wired to `/readyz` and `/healthz`.
- Shared image-tag rules in `tenant_config/version_rules.py` (released semver + optional `-hotfix.N`; dev may use pre-releases).
- Tenant config schema extended: `auth.*`, `features.interventions`, `portal.familyComparisonMode`, `attendance.*` policy fields.
- Production `bulkImport` requires per-tenant `erp.webhookSecretRef` or `erp.webhookSigningSecretRef` in config validation (resolved from `SA_SECRET_<REF>` at runtime).
- Regression suite: `tests/test_p0_regressions.py`, `tests/test_interventions.py`, `tests/test_mfa.py`, `tests/test_policy.py`, `tests/test_qa_contract.py`, `tests/test_version_rules.py`.

Run `alembic upgrade head` on PostgreSQL before serving traffic.

| `007_user_totp_mfa` | Adds `totp_secret_enc`, `totp_pending_secret_enc`, `mfa_enrolled_at` to `users` |

**Env / config changes (app):**

- No new required env vars. Existing `SECRET_KEY` is now enforced in production.
- Optional: `SKIP_STARTUP_DDL=1` for SQLite local dev when using Alembic only.

**Tenant settings (`settings_json` / config repo):**

- `features.interventions` — enable intervention workflow (default `false`).
- `auth.mfaEnabled`, `auth.mfaRequiredRoles` — enable MFA for listed roles.
- `portal.familyComparisonMode` — `self` or `cohort`.
- `attendance.countLateAsPresent`, `attendance.countExcusedAsPresent`.

## Breaking changes

- **Chart and export authorization** — Forbidden chart/export requests now return **404 Not Found** instead of **403 Forbidden**. Integrations that distinguished "exists but denied" from "not found" must treat both as inaccessible.
- **MFA** — Tenants with `auth.mfaEnabled` and role requirements force enrolment and TOTP on login for those roles. QA scripts that use `POST /api/auth/login` must handle `mfaPending` / `mfaEnrolmentNeeded` or keep MFA disabled on test tenants.
- **Deploy image tags (config repo)** — Staging and production tenant YAML must pin a released semver (`MAJOR.MINOR.PATCH` or `MAJOR.MINOR.PATCH-hotfix.N`). `latest` and pre-release tags (e.g. `0.1.0-SNAPSHOT`) are rejected by config validation and Helm.
- **Production SECRET_KEY** — App refuses to start with `DEBUG=false` and no `SECRET_KEY` (was previously warned-only with ephemeral key).

## Deploy notes

### Application image (this repo)

1. Merge and tag: `git tag v1.2.0 && git push origin v1.2.0` (triggers `.github/workflows/release.yml` → `ghcr.io/apoorv-a/school-analytics:1.2.0`).
2. Run migrations: `alembic upgrade head` (revisions through `007_user_totp_mfa`).
3. Helm deploy with explicit tag:

   ```bash
   helm upgrade school-analytics deploy/helm/school-analytics \
     --set-string image.tag=1.2.0 \
     --set-string operator.image.tag=1.2.0
   ```

4. Verify probes: `GET /healthz` → 200; `GET /readyz` → 200 when DB is up.

### Config repo (`school-analytics-config`)

Promote the shared image version in `environments/<env>/release.yaml` to `1.2.0` for staging/production. Per-tenant YAML changes (if enabling new features):

- Set `image.tag` to `1.2.0` (or rely on environment release file, per your promotion workflow).
- Optionally enable `features.interventions`, `auth.mfaEnabled` / `auth.mfaRequiredRoles`, and portal/attendance policy fields.
- Re-export JSON Schema after app upgrade: `python -m tenant_operator schema` (from this repo) and sync to config repo if schema drift checks apply.

**Post-deploy data (optional):**

- Backfill legacy attendance rows: `PYTHONPATH=. python scripts/backfill_attendance_term_id.py` (use `--dry-run` first).
